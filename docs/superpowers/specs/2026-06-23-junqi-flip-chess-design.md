# 军旗翻翻棋（暗棋）小游戏 — 设计文档

- 日期：2026-06-23
- 目标：实现一个可在浏览器中直接运行的军旗「翻翻棋（暗棋）」HTML 小游戏，支持人机对战（三档 AI）。

## 1. 概述

- 玩法：军旗翻翻棋（暗棋）。棋子背面朝下随机铺在棋盘上，玩家翻棋揭示、移动、交战。
- 棋盘：5 列 × 12 行 = 60 格，经典军旗布局，含**铁路**与**行营**两种地形（不做大本营）。双方共 50 子背面朝下随机铺在 50 格中，留 10 空格。
- 阵营确定：**人类永远先翻第一颗棋子**，翻开子颜色即成为人类阵营；AI 自动取另一方。
- 平台：纯前端，零依赖、零构建。普通 `<script>` 顺序引入 + 全局命名空间，双击 `index.html` 即玩。

## 2. 规则定义

### 2.1 棋子配置（每方 25 子）

| 棋子 | 数量 | 等级 |
|---|---|---|
| 司令 | 1 | 9 |
| 军长 | 1 | 8 |
| 师长 | 2 | 7 |
| 旅长 | 2 | 6 |
| 团长 | 2 | 5 |
| 营长 | 2 | 4 |
| 连长 | 3 | 3 |
| 排长 | 3 | 2 |
| 工兵 | 3 | 1（最低，但可挖雷、铁路上可转弯） |
| 炸弹 | 2 | 特殊 |
| 地雷 | 3 | 特殊 |
| 军旗 | 1 | 特殊 |

### 2.2 棋盘地形

5 列（C1–C5）× 12 行（R1 顶 → R12 底），中间 R6/R7 之间为楚河。`R`=铁路格，`X`=行营，`.`=普通格：

```
        C1 C2 C3 C4 C5
R1  :   .  .  .  .  .      ← 后排（原大本营行，现为普通格）
R2  :   R  R  R  R  R      ← 铁路（顶侧倒数第二行）
R3  :   R  X  .  X  R      ← 行营 C2,C4
R4  :   R  .  X  .  R      ← 中心行营 C3
R5  :   R  X  .  X  R      ← 行营 C2,C4
R6  :   R  R  R  R  R      ← 铁路（前线侧）
========楚河========
R7  :   R  R  R  R  R      ← 铁路（前线侧）
R8  :   R  X  .  X  R
R9  :   R  .  X  .  R
R10 :   R  X  .  X  R
R11 :   R  R  R  R  R      ← 铁路（底侧倒数第二行）
R12 :   .  .  .  .  .      ← 后排（普通格）
```

- 铁路横线：R2、R6、R7、R11；铁路竖线：C1、C5（贯通 R2–R11）。R1/R12 后排为普通格。
- 行营梅花位：上半 R3/R4/R5，下半 R8/R9/R10，对称镜像。每方 5 个行营。
- **楚河**：R6 与 R7 之间为楚河，跨河垂直连通**仅有三处**——左 C1、中 C3、右 C5。即 (R6,C1)↔(R7,C1)、(R6,C3)↔(R7,C3)、(R6,C5)↔(R7,C5) 连通；**(R6,C2)↔(R7,C2) 与 (R6,C4)↔(R7,C4) 不连通**（被楚河阻断）。所有跨 R6↔R7 的移动（普通1步、铁路直线扫描、工兵铁路 BFS）均受此约束——C2/C4 无法直接过河，须绕经 C1/C3/C5。

### 2.3 回合

- **人类永远先翻第一颗棋子**（据翻开子颜色确定人类阵营）；该次翻棋计为人类的第一步，翻棋后轮到 AI。因此不存在固定的「红方先手」——若人类翻到蓝色，则棋盘上先行移动的是 AI。
- 己方回合可执行：**翻棋**（翻开任意一颗未翻子）或 **移动**（移动一颗已翻己方子）。
- 首次翻棋定阵营仅生效一次。

### 2.4 移动

- **普通格**：已翻子上下左右走 1 格（空格=走子；已翻敌子=交战）。跨河（R6↔R7）仅 C1/C3/C5 可走，C2/C4 阻断。
- **铁路格**：已翻子在铁路上可沿连续铁路格**直线多步移动**（横向或纵向），直到遇到非铁路格、阻挡、楚河断点或攻击目标停下。**工兵在铁路上可转弯**（沿铁路网任意连通路径移动，BFS；跨河同样仅经 C1/C3/C5）。地雷、军旗不可移动。铁路上的子可在**独立的下一步**离开铁路到相邻普通/行营格——不可在同一步内滑行后离轨。
- **行营**：行营内棋子**不可被攻击**（安全）；敌方不可进入有子的行营；可进入空行营；行营内子可向 **8 个方向**走出（4 正交 + 4 对角，斜走规则见下条）。
- **斜路（行营斜走）**：斜走 1 步仅允许在「对角两端之一为行营」的格子对之间（全棋盘共 32 条斜边），双向可走：
  - 行营内棋子可向 4 个对角方向移动（自身一端即行营）；
  - 与行营斜向相邻的格子（普通格或铁路格）上的棋子，也可斜走进出该行营（斜向攻击入营仍受行营免疫约束）。
  - 梅花形行营的外圈 ↔ 中心属于其中 8 条：上半 (R3,C2)/(R3,C4)/(R5,C2)/(R5,C4) ↔ (R4,C3)，下半 (R8,C2)/(R8,C4)/(R10,C2)/(R10,C4) ↔ (R9,C3)；其余斜边为行营与其四周斜邻格之间的连线。**不做全盘经典斜路。**

### 2.5 交战（攻击者进入防守方格子）

前提：双方都已翻开才能交战；未翻子不能被攻击，只能被翻。行营内防守方不可被攻击（攻击者无法进入有子的行营）。

- 大吃小：等级高者存活并占据该格，败者移除。
- 同级相遇：同归于尽，两子移除，格子变空。
- 工兵 vs 地雷：工兵排除地雷，工兵存活占格，地雷移除。
- 非工兵 vs 地雷：撞雷者阵亡，地雷保留原地。
- 炸弹 vs 任何已翻敌子：同归于尽，两子移除。
- 炸弹 vs 地雷：两子同归于尽（炸弹引爆地雷）。
- 炸弹 vs 对方已翻军旗：两子同归于尽，且**军旗被毁 → 旗方立即判负（攻击方胜）**。
- 前置限制：攻击对方军旗（吃旗或炸弹炸旗均含）须先拔光其全部 3 颗地雷，否则为非法走法，见 §2.6。

### 2.6 胜负

- 攻击军旗的前置条件：必须**先拔光对方全部 3 颗地雷**（`minesLost` 记每方已损失雷数）；未拔满前任何对其军旗的攻击（含炸弹炸旗）均为非法走法。
- 军旗被毁 → 攻击方立即胜：吃旗（攻击者存活占格）或炸弹炸旗（两子同归于尽）均判旗方负。
- 轮到的一方无合法行动（无未翻子可翻 且 无可移动子）→ 该方负。**该判定优先于和棋**：即使困局计数已达上限，只要轮转方无合法行动即判负，而非和棋。
- 困局兜底：连续 **40 回合**（= 双方各 40 步 = 80 个单方动作 ply）无吃子且无翻棋则判和。

## 3. 模块与文件结构

```
liu/game/
├── index.html              # 棋盘容器、HUD、控制按钮、规则弹窗
├── style.css               # 棋盘网格、地形样式、棋子样式、阵营色、动画、响应式
└── js/
    ├── constants.js        # 棋子类型表、等级、数量、棋盘尺寸、难度枚举
    ├── board.js            # 棋盘地形：哪些格是铁路/行营/普通，斜路邻接表
    ├── state.js            # 游戏状态：棋盘数组、回合、阵营、地雷/吃子记账、胜负（唯一真源）
    ├── rules.js            # 纯函数：合法走法生成（含铁路多步/工兵转弯/行营/斜路）、交战结算、胜负判定
    ├── ai.js               # 三档AI：随机/启发式/expectimax+概率
    ├── ui.js               # 渲染、地形底纹、翻棋/移动/吃子 SVG 动画、非法操作格子闪红、选中高亮、合法步提示、终局结算浮层（均尊重 prefers-reduced-motion）；事件绑定
    └── main.js             # 入口：初始化、连接 state/rules/ai/ui、回合调度
└── tests/
    ├── rules.test.js       # 规则纯函数单测（Node 内置 node:test，零依赖）
    ├── state.test.js       # 状态流转/交战落盘/胜负与和棋单测
    └── ai.test.js          # AI 合法性与剩余分布不变式单测
```

### 3.1 职责边界

- `board.js`：纯数据，定义 60 格的地形类型（`railway`/`camp`/`normal`）、斜路邻接关系，以及**跨河连通表**（R6↔R7 仅 C1/C3/C5 连通，C2/C4 阻断），供 rules/ui 共用。所有邻接判定（普通1步、铁路扫描、工兵 BFS、斜路）统一经过 `board.isAdjacent(a,b)` / `board.railConnected(a,b)` 查询。
- `rules.js`：纯逻辑核心，输入棋盘状态输出合法动作与结算结果，不碰 DOM，可单测、可被 AI 复用。铁路多步走法用 BFS/直线扫描生成，工兵在铁路上用 BFS（可转弯）。
- `state.js`：持有唯一真源（`board`、`turn`、`playerSide`、`winner`），暴露 `applyMove` 等变更方法。
- `ai.js`：只依赖 `rules.js` 的合法走法生成，返回一个动作；难度通过参数注入。
- `ui.js`：监听 state 变化重渲染，把玩家点击转成动作提交给 `main.js`。
- `main.js`：粘合层——人类提交动作→state 更新→若轮到 AI 调 `ai.chooseMove`→再更新→渲染。

### 3.2 加载方式

普通 `<script>` 顺序引入，挂到全局 `Junqi` 命名空间对象，规避 `file://` 下 ES module 限制，双击即玩。

## 4. 数据模型与数据流

### 4.1 数据模型

```
terrain = 'normal' | 'railway' | 'camp'   // 由 board.js 按 (row,col) 查表得出

cell = {
  piece: { type, rank, side } | null,     // null=空格
  revealed: boolean                        // 是否已翻开
}
// piece.side 仅在 revealed=true 时对外可见；困难档 AI 用剩余分布概率推断未翻子

gameState = {
  board: cell[60],                         // 索引 = row*5 + col
  rows: 12, cols: 5,
  turn: null | 'red' | 'blue',             // 首次翻棋前为 null（人类先翻棋）
  playerSide: null | 'red' | 'blue',       // 翻第一颗时确定
  aiSide: null | 'red' | 'blue',
  sidesAssigned: boolean,
  winner: null | 'red' | 'blue' | 'draw',
  staleCount: number,                      // 无吃翻的单方动作(ply)计数，达 80（=40 回合）判和
  minesLost: { red: number, blue: number },// 每方已损失地雷数；拔满 3 颗才可攻击其军旗
  captured: { 'type:side': number },       // 已被吃/移除的子，供困难档 AI 剩余分布扣减
  lastMove: object | null                  // 最近一步描述（供 UI 标记/提示），开局为 null
}

action =
  | { kind: 'flip', index }
  | { kind: 'move', from, to }
```

### 4.2 数据流（一次回合）

```
人类点击格子
  → ui.js 判定点击语义（翻棋/选中/移动）
  → main.js 提交 action
  → state.applyMove(action)
       → 若首次翻棋且未定阵营：据翻开子颜色定 playerSide
       → 调 rules.resolveBattle 结算交战
       → 更新 turn、staleCount、判胜负
  → state 通知 ui 重渲染
  → 若 !winner && turn === aiSide：
       → ai.chooseMove(state, difficulty) 返回 action
       → state.applyMove(action) → 渲染
```

### 4.3 关键不变量

- 未翻子的 `piece.side` 不对外泄露给渲染（ui 仅在 `revealed` 时显示颜色）；困难档 AI 不"作弊读取"，而是用剩余分布估算概率。
- 胜负在每次 `applyMove` 后立即检查并锁定，`winner` 非空后拒绝任何 action。
- 行营安全规则在 `rules` 合法走法生成阶段即过滤：攻击者无法选中「进入有子行营」作为目标。

### 4.4 AI 困难档的不完全信息处理

- 维护「剩余未翻子集合」（已知哪些已出现），未翻格子里的子按剩余分布加权。
- 剩余分布同时扣除已被吃/移除的子（`state.captured`，含被吃子、同归于尽与攻击方阵亡），保证不变式 **Σ剩余分布 == 当前暗格数** 全程成立。
- 估值函数：棋子价值表（司令高，工兵因能挖雷有额外值）+ 阵型/暴露风险 + 铁路机动性。
- 搜索深度 2~3 层 expectimax，节点数上限设阈值防爆栈超时。

## 5. AI 设计（三档）

- 简单：随机合法走法（偶尔翻棋）。
- 普通：贪心启发式——能吃就吃大的、避开送大子、危险才翻棋、利用铁路机动。
- 困难：对已翻开棋子做有限深度 expectimax，未翻子按剩余分布算概率（评估踩雷/撞炸弹风险）。搜索超限回退普通档启发式。

## 6. 错误处理、测试与边界

### 6.1 错误处理

- 玩家非法操作（攻击未翻子、移动地雷/军旗、非己方回合点棋、攻击行营内有子目标）：UI 层拦截，轻量提示（toast/格子闪红），不改状态、不抛异常。
- 状态已结束（`winner` 非空）：棋盘点击忽略；最后一步动画播完后延迟弹出**结算浮层**（「再来一局」/「回顾棋盘」）。
- AI 无合法走法：`rules` 判为负，正常结算。
- AI 思考超时兜底：困难档搜索设节点/时间上限，超限回退普通档启发式。
- 翻棋定阵营冲突：仅首次翻棋生效，后续翻棋只揭示不再改 `playerSide`。

### 6.2 测试

现有 3 个测试文件（Node ≥ 18 内置 `node:test`，零依赖）：`tests/rules.test.js`、`tests/state.test.js`、`tests/ai.test.js`，运行 `npm test`（或 `node --test` 三文件）。
- 合法走法生成：普通1步、铁路直线多步、**铁路滑行不可同一步离轨（离轨须独立一步）**、工兵铁路转弯、行营安全（不可被攻击）、**行营内 8 方向移动**、**凡对角一端为行营即可斜走 1 步（含非行营→行营的可逆斜走）**、地雷/军旗不可动、**楚河阻断（C2/C4 不可跨 R6↔R7）**。
- 交战结算全分支：大吃小、同级同归、工兵挖雷、非工兵撞雷（雷留）、炸弹同归、炸弹遇雷同归、**炸弹炸旗（军旗被毁、旗方判负）**。
- 胜负判定：**夺旗/炸旗胜（前置：须先拔光对方 3 颗地雷，未拔满攻击军旗为非法）**、无路可走负、**无路可走优先于和棋**、困局和（**40 回合阈值，即 staleCount 达 80 ply**；40 ply = 20 回合不判和）。
- 首次翻棋定阵营逻辑（翻棋后轮到 AI）、`minesLost`/`captured` 计数落盘。
- `ai.js`：固定棋盘快照断言三档 AI 返回合法动作；困难档在确定性局面下不踩明显送死（软断言）；**captured 分布不变式：Σ剩余分布 == 暗格数，整局模拟全程成立**。
- 手动验证：UI 跑通完整对局、AI 三档可切换、重开按钮有效（用 verify 技能实跑）。

### 6.3 边界与可玩性

- 棋盘 5×12 在窄屏纵向滚动；`style.css` 用 `clamp()` 缩放格子 + 触摸友好尺寸。
- 困局兜底：连续 40 回合（= 80 个单方动作 ply）无吃子、无翻棋则判和，防死循环；无路可走判负优先于该兜底。

## 7. 非目标（明确不做）

- 不做联网对战。
- 不做布阵阶段（翻翻棋为随机暗开局）。
- 不做悔棋/复盘回放。
- 不做音效。
- 不做大本营（后排 R1/R12 作为普通格处理）。
- 不做全盘经典斜路：斜走仅限与行营斜相邻的方向（对角两端之一为行营即可斜走 1 步，全棋盘共 32 条斜边），不做经典军旗的全盘斜线网。
