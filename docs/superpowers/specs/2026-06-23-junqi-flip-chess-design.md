# 军旗翻翻棋（暗棋）小游戏 — 设计文档

- 日期：2026-06-23
- 目标：实现一个可在浏览器中直接运行的军旗「翻翻棋（暗棋）」HTML 小游戏，支持人机对战（三档 AI）。

## 1. 概述

- 玩法：军旗翻翻棋（暗棋）。棋子背面朝下随机铺满棋盘，玩家翻棋揭示、移动、交战。
- 棋盘：5 行 × 10 列 = 50 格，开局双方共 50 子背面朝下铺满，无空格。
- 阵营确定：首次翻开一颗棋子时，该棋子颜色即成为翻棋者阵营；AI 自动取另一方。
- 平台：纯前端，零依赖、零构建。普通 `<script>` 顺序引入 + 全局命名空间，双击 `index.html` 即玩。

## 2. 规则定义

### 2.1 棋子配置（每方 25 子）

| 棋子 | 数量 | 等级 |
|---|---|---|
| 司令 | 1 | 9 |
| 军长 | 1 | 8 |
| 师长 | 2 | 7 |
| 旅长 | 2 | 6 |
| 团长 | 2 | 5 |
| 营长 | 2 | 4 |
| 连长 | 3 | 3 |
| 排长 | 3 | 2 |
| 工兵 | 3 | 1（最低，但可挖雷） |
| 炸弹 | 2 | 特殊 |
| 地雷 | 3 | 特殊 |
| 军旗 | 1 | 特殊 |

### 2.2 回合

- 红方先手。
- 己方回合可执行：**翻棋**（翻开任意一颗未翻子）或 **移动**（移动一颗已翻己方子）。
- 首次翻棋时据翻开子颜色确定翻棋者阵营，仅生效一次。

### 2.3 移动

- 已翻棋子向上下左右相邻一格移动：到空格=走子；到已翻敌子=交战。
- **地雷、军旗不可移动**（只能被翻开，不能主动移动）。

### 2.4 交战（攻击者进入防守方格子）

前提：双方都已翻开才能交战；未翻子不能被攻击，只能被翻。

- 大吃小：等级高者存活并占据该格，败者移除。
- 同级相遇：同归于尽，两子移除，格子变空。
- 工兵 vs 地雷：工兵排除地雷，工兵存活占格，地雷移除。
- 非工兵 vs 地雷：撞雷者阵亡，地雷保留原地。
- 炸弹 vs 任何已翻敌子：同归于尽，两子移除。
- 炸弹 vs 地雷：两子同归于尽（炸弹引爆地雷）。

### 2.5 胜负

- 吃掉对方军旗 → 立即胜。
- 对方无合法行动（无未翻子可翻 且 无可移动子）→ 对方负。
- 困局兜底：连续 40 回合无吃子且无翻棋则判和。

## 3. 模块与文件结构

```
liu/game/
├── index.html              # 棋盘容器、HUD、控制按钮、规则弹窗
├── style.css               # 棋盘网格、棋子样式、阵营色、动画、响应式
└── js/
    ├── constants.js        # 棋子类型表、等级、数量、棋盘尺寸、难度枚举
    ├── state.js            # 游戏状态：棋盘数组、回合、阵营、历史、胜负
    ├── rules.js            # 纯函数：合法走法生成、交战结算、胜负判定（可单测）
    ├── ai.js               # 三档AI：随机/启发式/expectimax+概率
    ├── ui.js               # 渲染、动画、选中高亮、提示；事件绑定
    └── main.js             # 入口：初始化、连接 state/rules/ai/ui、回合调度
└── tests/
    └── rules.test.js       # Node 内置 node:test，零依赖
```

### 3.1 职责边界

- `rules.js`：纯逻辑核心，输入棋盘状态输出合法动作与结算结果，不碰 DOM，可单测、可被 AI 复用。
- `state.js`：持有唯一真源（`board`、`turn`、`playerSide`、`winner`），暴露 `applyMove` 等变更方法。
- `ai.js`：只依赖 `rules.js` 的合法走法生成，返回一个动作；难度通过参数注入。
- `ui.js`：监听 state 变化重渲染，把玩家点击转成动作提交给 `main.js`。
- `main.js`：粘合层——人类提交动作→state 更新→若轮到 AI 调 `ai.chooseMove`→再更新→渲染。

### 3.2 加载方式

普通 `<script>` 顺序引入，挂到全局 `Junqi` 命名空间对象，规避 `file://` 下 ES module 限制，双击即玩。

## 4. 数据模型与数据流

### 4.1 数据模型

```
cell = {
  piece: { type, rank, side } | null,   // null=空格
  revealed: boolean                      // 是否已翻开
}
// piece.side 仅在 revealed=true 时对外可见；困难档 AI 用剩余分布概率推断未翻子

gameState = {
  board: cell[50],                       // 索引 = row*10 + col
  rows: 5, cols: 10,
  turn: 'red' | 'blue',
  playerSide: 'red' | 'blue',            // 翻第一颗时确定
  sidesAssigned: boolean,
  winner: null | 'red' | 'blue' | 'draw',
  history: [action, ...]
}

action =
  | { kind: 'flip', index }
  | { kind: 'move', from, to }
```

### 4.2 数据流（一次回合）

```
人类点击格子
  → ui.js 判定点击语义（翻棋/选中/移动）
  → main.js 提交 action
  → state.applyMove(action)
       → 若首次翻棋且未定阵营：据翻开子颜色定 playerSide
       → 调 rules.resolveBattle 结算交战
       → 更新 turn、判胜负
  → state 通知 ui 重渲染
  → 若 !winner && turn === aiSide：
       → ai.chooseMove(state, difficulty) 返回 action
       → state.applyMove(action) → 渲染
```

### 4.3 关键不变量

- 未翻子的 `piece.side` 不对外泄露给渲染（ui 仅在 `revealed` 时显示颜色）；困难档 AI 不"作弊读取"，而是用剩余分布估算概率。
- 胜负在每次 `applyMove` 后立即检查并锁定，`winner` 非空后拒绝任何 action。

### 4.4 AI 困难档的不完全信息处理

- 维护「剩余未翻子集合」（已知哪些已出现），未翻格子里的子按剩余分布加权。
- 估值函数：棋子价值表（司令高，工兵因能挖雷有额外值）+ 阵型/暴露风险。
- 搜索深度 2~3 层 expectimax，节点数上限设阈值防爆栈超时。

## 5. AI 设计（三档）

- 简单：随机合法走法（偶尔翻棋）。
- 普通：贪心启发式——能吃就吃大的、避开送大子、危险才翻棋。
- 困难：对已翻开棋子做有限深度 expectimax，未翻子按剩余分布算概率（评估踩雷/撞炸弹风险）。搜索超限回退到普通档启发式。

## 6. 错误处理、测试与边界

### 6.1 错误处理

- 玩家非法操作（攻击未翻子、移动地雷/军旗、非己方回合点棋）：UI 层拦截，轻量提示（toast/格子闪红），不改状态、不抛异常。
- 状态已结束（`winner` 非空）：所有点击忽略。
- AI 无合法走法：`rules` 判为负，正常结算。
- AI 思考超时兜底：困难档搜索设节点/时间上限，超限回退普通档启发式。
- 翻棋定阵营冲突：仅首次翻棋生效，后续翻棋只揭示不再改 `playerSide`。

### 6.2 测试

`rules.js` 为纯函数，配套 `tests/rules.test.js`（Node `node:test`，零依赖）：
- 合法走法生成（含地雷/军旗不可动）。
- 交战结算全分支：大吃小、同级同归、工兵挖雷、非工兵撞雷（雷留）、炸弹同归、炸弹遇雷同归。
- 胜负判定：夺旗胜、无路可走负、困局和。
- 首次翻棋定阵营逻辑。
- `ai.js`：固定棋盘快照断言三档 AI 返回合法动作；困难档在确定性局面下不踩明显送死（软断言）。
- 手动验证：UI 跑通完整对局、AI 三档可切换、重开按钮有效（用 verify 技能实跑）。

### 6.3 边界与可玩性

- 棋盘 5×10 在窄屏横向滚动；`style.css` 用 `clamp()` 缩放格子 + 触摸友好尺寸。
- 困局兜底：连续 40 回合无吃子、无翻棋则判和，防死循环。

## 7. 非目标（明确不做）

- 不做联网对战。
- 不做布阵阶段。
- 不做悔棋/复盘回放。
- 不做音效。
- 不做完整陆战棋（铁路/行营/大本营）。
