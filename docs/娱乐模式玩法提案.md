# 军旗翻翻棋 · 娱乐模式候选玩法提案

> 日期：2026-10-23
> 状态：提案（未排期、未实现）
> 基线：v1.4.0（经典 / 娱乐·军衔升级 / 娱乐·镜像明棋）
> 目的：在现有两种娱乐模式之外，给出一批**趣味明确、与现有架构兼容、成本可估**的新玩法，并给出开发难度与推荐评级。

---

## 0. 结论摘要

1. **下一版最推荐先做「招降纳叛」**：只改战斗结算一处，趣味极高（以战养战、滚雪球），难度约 ⭐⭐，是性价比最高的一张牌。
2. **「乘胜追击」是最有爽感、但成本也明显更高的一张牌**：吃子后可继续行动，能打出连击高光；需要改回合流 + AI 搜索，建议排在招降纳叛之后。
3. **「自选布阵」适合做旗舰内容**：策略深度最高、最像"正统军棋"，但完整拖拽布阵 UI 成本高。建议先做"三套模板布阵"的 MVP（⭐⭐），完整版放远期。
4. **「火药桶 / 闪电战 / 无雷速攻 / 夺旗行军」是一组低成本快棋包**：每个 ⭐~⭐⭐，适合一起做成"快棋玩法"分类，快速丰富模式列表。
5. **「战场事件 / 军饷 / 迷雾 / Roguelike」不建议现在做**：要么 AI 无法建模、要么需要信息模型或元系统改造，投入产出比不划算。
6. 结合当前主要游玩场景（**大师档 AI + 安卓 APK**），优先选**不降低 AI 强度、移动端友好**的玩法；「战场事件」这类 AI 无法建模的玩法会明显削弱大师档体验，建议后置。

三个关键工程判断：

- **规则类玩法很便宜**：`state.applyBattle`（`js/state.js:109`）是真实对局与 AI 搜索共用的唯一战斗落盘口，改这里就能同时改变玩家和 AI 的世界。
- **回合流玩法很贵**：`state.turn` 是全局唯一回合开关，`state.applyMove`（`js/state.js:174`）、`ai.applyAction`（`js/ai.js:491`）、`ai.applyOnClone`（`js/ai.js:565`）、悔棋快照、`main.scheduleAI`（`js/main.js:240`）都依赖"一步一换手"。
- **信息类玩法最贵**：当前 `cell.revealed` 是**双方共享的公开信息**，没有"某一方可见"的视图层。任何"己方可见/敌方不可见"的玩法都需要新增视图模型，不能靠临时改 `revealed` 糊过去。

## 1. 现有模式与扩展位

### 1.1 现有两种娱乐模式的共同点

- 都是 **variant（玩法）与 mode（人机/双人）正交**：`state.variant` 是纯数据字段，随快照自动进 AI Worker。
- 都**不改变经典模式行为**：经典路径的断言与回归测试是硬护栏。
- 都靠 `constants.VARIANTS` 枚举 + `createInitialState({mode, variant})` 分支 + UI 玩法说明落地。

这意味着新玩法可以沿用同一套"加法"模式，不必重写游戏。

### 1.2 关键扩展位

| 层 | 位置 | 能改什么 | 改动波及 |
|---|---|---|---|
| 常量 | `js/constants.js:16` `PIECES`、`:47` `VARIANTS` | 棋子数量、军衔、玩法枚举 | 发牌、AI 剩余分布、记牌器 |
| 发牌 | `js/state.js:52` `createInitialState` | 开局布局、明暗、分边、先手 | 镜像明棋、布阵、种子局 |
| 战斗 | `js/state.js:109` `applyBattle` | 吃子结果、升级、策反、复活 | 真实对局 + AI make/unmake + 克隆搜索 |
| 回合 | `js/state.js:174` `applyMove` | 翻/走/换手/连击 | AI `applyAction`/`applyOnClone`、悔棋、调度 |
| 交战规则 | `js/rules.js:14` `resolveBattle` | 大吃小、炸弹、地雷、军旗 | 5 处 AI 调用点（`ai.js:132/185/222/610/653`） |
| 走法 | `js/rules.js:49` `legalMoves`；`js/constants.js:37` `IMMOBILE` | 可动性、特殊走法 | AI 枚举动作、UI 选中 |
| AI 估值 | `js/ai.js:47` `valueOfPiece` | 新棋子/新机制的价值 | 材料、威胁、排序、剪枝 |
| 回合调度 | `js/main.js:240` `scheduleAI`；`js/main.js:191` `commitAction` | 谁在什么时候走、悔棋粒度 | 人机/双人、Worker |
| 渲染 | `js/ui.js:232` `render`；`:670` `trackerData` | 棋子外观、记牌器口径 | 所有玩法 |
| 入口 | `index.html:96` 玩法 seg | 玩法选择 UI | 模式弹窗、说明、金标 |

### 1.3 成本分级

| 级别 | 含义 | 典型改动 | 工期 |
|---|---|---|---|
| **C0** | 纯 UI/调度 | 计时器、提示、展示 | 半天内 |
| **C1** | 结算/常量微调 | `applyBattle` 或 `resolveBattle` 加分支、棋子数量表 | 1~2 天 |
| **C2** | 回合流/走法改造 | `applyMove` + `applyAction`/`applyOnClone` + AI 搜索 + 悔棋 | 3~5 天 |
| **C3** | 信息模型改造 | 每方可见性、暗子身份、视图层 | 1~2 周 |
| **C4** | 新阶段/新系统 | 布阵阶段、事件引擎、元进度、存档 | 1~2 周起 |

> 评估口径：趣味性看"新决策 + 高光时刻 + 重玩性"；难度按上表；推荐度 S > A > B > C。

## 3. 详细提案

### 3.1 招降纳叛（策反）　推荐 S　难度 ⭐⭐

**核心规则**

- 攻击方**获胜**（攻击者存活，非同归）且防守方是**普通棋子**（非炸弹/地雷/军旗）时，防守方不阵亡，而是**翻为攻击方阵营**。
- 落位：攻击者占据目标格（沿用现有 `applyBattle` 的落盘）；被策反的子落在**攻击者原来的格子**，明置。
- 同归、炸弹、地雷、军旗、攻击方战败：全部沿用经典规则。
- 可选平衡：每方策反上限 3 子；或策反子军衔 -1（最低到工兵，工兵不再降）。建议先不限，观察雪球强度后再调。

**为什么好玩**

- "以战养战"：每一次正确交换都在壮大自己，越打越强，天然产生滚雪球高光。
- 交换判断被彻底改写：以前"拿司令换军长"是亏，现在"换"与"策反"是两种完全不同的收益模型。
- 防守方也会更谨慎：把弱子送到强子嘴边，等于给对面送兵。

**实现要点**

- 主改动在 `js/state.js:109` `applyBattle`：在现有 `res.to` 落盘之后、`captured` 计数之前加分支。
  - 被策反子**不写入** `state.captured`（它仍在棋盘上）。
  - `state.board[from]` 从"清空"改为"放入改旗后的克隆棋子"。
  - 返回 `conversion: { type, fromRank, side }`，随 `lastMove.battle` 给 UI 播报。
- `ai.applyAction` / `applyOnClone` 都调用 `STATE.applyBattle`，战斗部分自动共享；但 undo 记录需确认 `fromCell`/`toCell` 两个 cell 都被回填（现有代码已经保存这两格，基本兼容）。
- `remainingDistribution`（`js/ai.js:18`）假设"每方固定 25 子"；策反会打破该假设，导致某些 `rem[type:side]` 变负。MVP 先 `Math.max(0, …)` 夹紧，并在 AI 估值里接受近似；进阶做法是记录 `converted` 计数。
- 记牌器（`js/ui.js:670` `trackerData`）同样按固定数量算"未翻"，策反后可能出现负数。建议该玩法下把左侧面板改为「战场兵力」：显示双方当前存活/策反数，不再显示"未翻透视"。
- UI：toast「⚔ 红方 连长 策反了 蓝方 排长」+ 专属音效；棋子外观可加一个小小的"降"字角标或反向金环，区分原装子与策反子。

**风险**

- 雪球可能过强，尤其大师 AI 会迅速滚起来。用"每方上限 3"或"策反子降一级"做开关，A/B 验收。
- 策反会改变双方子力构成，AI 的剩余分布与记牌器口径需要明确"近似"边界。

**MVP 切法**：不做上限、不做降级，先上线看体验；记牌器在该玩法下隐藏"未翻透视"。

### 3.2 乘胜追击（连击）　推荐 S　难度 ⭐⭐⭐

**核心规则**

- 你的一次走子**打赢战斗**（攻击者存活；同归不算；夺旗终局不算）后，**同一颗棋子**可以立刻再走一步（可走空位，也可继续攻击），但不能翻棋。
- 连击可以连续触发；玩家随时可以点「结束行动」把回合交给对方。
- 建议每回合连击上限 2 次（即最多 3 次行动），防止单子无限扫场；上限可配置。

**为什么好玩**

- 一颗强子打出连击、连续吃掉两三颗子，是天然的"高光时刻"，非常适合短视频/截图传播。
- 走位和阵型价值上升：给强子留出连续攻击线路，成为新的布局目标。
- 风险对称：连击中的子如果下一击撞死，会一次性亏掉两颗子的价值。

**实现要点**

- `state` 新增 `chain = { side, index, count }`（或 `pending`）。`applyMove` 在战斗获胜后**不换手**，并设置 `chain`；走空位、同归、战败、主动结束则正常换手。
- `R.checkWinner` 需要感知"连击中"：连击方的子若已无合法走法，应结束连击而不是判负。
- `ai.applyAction` / `applyOnClone` 必须同步这套换手逻辑；否则 AI 搜索里"一步"与"一回合"的语义会和真实对局脱节。
- AI 搜索：最省事的做法是把"连击"当成**同一动作的延伸**——根节点对每个获胜走法做 1~2 层同子续走 greedy 展开，再进入正常搜索。不要直接把深度加一，否则浅层搜索会被连击分支撑爆。
- UI：选中态保持在该子上，显示「可继续追击 / 结束行动」；`main.commitAction` 只有在**回合开始**时压悔棋快照，连击续走不压栈，这样悔棋仍是"撤销整回合"。
- `main.scheduleAI` 在连击未结束时不得调度 AI；`soundAfterApply` 的终局/升级播报需按连击次数去重。

**风险**

- 回合流改造会波及悔棋、AI 调度、双人同屏提示，测试面较大。
- AI 若只做 greedy 连击，强度会明显弱于人类；需要单独的 AI 回归与 A/B。

**MVP 切法**：只允许"同一颗子再走一步"，不允许继续连击；AI 只做 1 层续走。体验成立后再放开连击上限。

### 3.3 火药桶（炸弹狂欢）　推荐 A　难度 ⭐⭐

**核心规则**

- 双方炸弹从 2 颗提升到 **4 颗**；为保持每方 25 子，移除 1 颗连长 + 1 颗排长（或按 A/B 调整）。
- 炸弹仍可正常移动，与任何子同归；炸军旗仍是旗方判负。
- 其余规则不变。

**为什么好玩**

- 炸弹是最有戏剧性的棋子：一换一、炸司令、炸军旗，全是高光。
- 炸弹变多后，"大子"不敢横着走，行营和铁路的价值上升，节奏更快更刺激。

**实现要点**

- 新增 `pieceCounts(variant)`（或 `variantConfig(variant).pieceCounts`），替换以下硬编码：
  - `js/state.js:15` `buildPieces`
  - `js/ai.js:22` `remainingDistribution`
  - `js/ui.js:588/594` 记牌器初始化、`:674` `trackerData`
- `PIECES_PER_SIDE` 仍为 25（只是换构成），棋盘容量不变。
- AI 估值：炸弹 35 分在 4 颗时略高，可下调到 30 左右做 A/B；不调也能玩。

**风险**

- 低：纯数量调整，搜索与回合流不变。
- 需要一套"变体棋子数量"的公共入口，否则以后每加一个改数量的玩法都要改四处。

**MVP 切法**：先做 4 炸弹版本；如果节奏太乱，回退到 3 炸弹。

### 3.4 闪电战（限时）　推荐 A　难度 ⭐

**核心规则**

- 人类回合限时 **20 秒**（可在设置里选 15/20/30 秒）；倒计时归零自动执行一个随机合法动作（优先翻棋，其次随机走子）。
- AI 回合不计时；弹窗打开、页面隐藏、终局、悔棋后重置计时。
- 可选硬核开关：超时直接判负（默认关闭，随机走更友好）。

**为什么好玩**

- 手机端的碎片时间友好，避免长考；倒计时本身制造紧张感。
- 对 AI 强度影响小，适合作为"所有玩法的可选修饰"。

**实现要点**

- 纯 `js/main.js` + `index.html`/`style.css`：
  - 在 `start()/reset()/undo()/commitAction()` 处重置计时。
  - 用 `setTimeout` + `performance.now()` 做显示，避免后台标签页漂移。
  - 超时动作从 `R.enumerateActions(state, state.turn)` 里随机取，走 `commitAction`，保证入悔棋栈与音效一致。
- 不需要改 `rules/state/ai`。

**风险**

- 极低。唯一注意：不要在 AI 思考期间对玩家倒计时；`state.controllers[state.turn] === 'human'` 才启动。

**MVP 切法**：固定 20 秒，先不做设置项。

### 3.5 无雷速攻　推荐 B+　难度 ⭐

**核心规则**

- 双方地雷 **0 颗**（或 1 颗，二选一），军旗从开局起就可被攻击。
- 困局和棋阈值从 40 回合降到 **20 回合**，逼迫进攻。
- 其余规则不变，每方 25 子由其他兵种补齐。

**为什么好玩**

- 一局 3~5 分钟，适合快节奏对局；没有"拔雷"阶段，战斗更直接。
- 军旗位置从开局就是真正的秘密核心，护旗/找旗的博弈更纯粹。

**实现要点**

- 与火药桶共用 `pieceCounts(variant)`。
- `legalMoves` 的军旗保护条件（`js/rules.js:66`）改为"该玩法下 `minesRequired = 0`"。
- `checkWinner` 的 `STALE_LIMIT` 改为按玩法取值（`C.STALE_LIMIT` 目前是常量）。
- AI 的 `valueOf('mine')`、`threatWeight` 里"拔雷"相关逻辑在该玩法下天然失效，不需要特殊分支，但估值会略偏；可接受。

**风险**

- 低。和棋阈值与军旗保护是两处明确分支。
- 少了地雷后，工兵价值下降（只剩铁路转弯），AI 估值不必强行修，先观察。

**MVP 切法**：0 雷 + 20 回合阈值，与闪电战打包成「快棋」分类。

### 3.6 夺旗行军　推荐 A-　难度 ⭐⭐

**核心规则**

- 军旗可以像普通棋子一样**正交移动 1 步**，但不能：
  - 进入行营（否则行营免疫会让军旗变成无敌）；
  - 主动攻击（只能走到空格）；
  - 在铁路上滑行多步。
- 地雷仍需拔满 3 颗才能吃旗；吃旗/炸旗仍立即终局。
- 其余规则不变。

**为什么好玩**

- 军旗从"死靶子"变成"会跑的核心"，多了护旗、诱敌、弃旗保帅的博弈。
- 对手以为你在守旗，其实旗已经挪走；心理战拉满。

**实现要点**

- `C.IMMOBILE` 目前是静态数组（`js/constants.js:37`），改为按玩法取：地雷恒不可动，军旗在该玩法可动。
- `js/rules.js:49` `legalMoves` 对 `flag` 加特殊分支：只允许正交 1 步到空格、禁入营。
- AI 的 `enumerateActions` 走 `legalMoves`，自动获得新走法；但 `valueOfPiece(flag)=1000` 会让 AI 几乎不敢动旗。可以接受（AI 保守护旗），也可以在估值里加"旗被威胁时允许挪位"的小项。
- UI：规则说明、上一步描述、aria 文案需要把"军旗不可移动"改成条件文案。

**风险**

- 中低。主要风险是"军旗可动 + 行营免疫"的无敌组合，必须禁入营。
- 双人同屏下，双方都能看到旗在动，心理战效果略弱；人机模式更有趣。

**MVP 切法**：只允许正交 1 步、禁入营、禁攻击。

### 3.7 自选布阵　推荐 S（旗舰）　难度 ⭐⭐（模板）/ ⭐⭐⭐⭐（完整）

**核心规则**

- 开局增加"布阵阶段"：红方在**下半场 25 个非行营格**摆好自己的 25 颗子，蓝方在**上半场 25 个非行营格**摆好自己的 25 颗子。
  - 棋盘 12×5，每半场 6×5=30 格，减去 5 个行营，恰好 **25 格**，与 25 颗子一一对应，容量天然吻合。
- 布阵完成后进入正常对局：双方阵营固定（红先），所有棋子仍然背面朝下；玩家知道自己摆的阵，对手不知道。
- 人机模式：玩家摆阵，AI 从预设阵型里选一套或随机摆；界面提供"布阵图"按钮，玩家可随时查看自己的布局（AI 不读）。
- 双人同屏：双方依次布阵，中间加"请对方回避"遮罩；对局中"查看布阵图"会泄露，建议双人模式禁用该按钮或改为"按住查看"。

**为什么好玩**

- 这是最接近"正统军棋"的体验：旗放哪、雷怎么埋、大子压哪条线，全是自己的决策。
- 重玩性极高：同一套规则下，不同阵型就是不同的开局剧本。
- 与现有"随机铺子"形成鲜明对比，是真正能撑起一个版本的旗舰玩法。

**实现要点**

- **MVP（模板布阵，⭐⭐）**：
  - `createInitialState` 增加 `variant === 'formation'` 分支：按所选模板把 25 子放进己方半场，AI 随机一套。
  - 新增 3 套模板（均衡 / 重雷 / 重攻）与一个简单的布阵图弹层；不做拖拽。
  - 阵营固定、红先；所有子背朝下，翻棋规则不变。
  - 改动集中在 `state.js` + `index.html` + `ui.js`，AI 搜索零改动。
- **完整版（拖拽布阵，⭐⭐⭐⭐）**：
  - 新增 `phase: 'setup' | 'play'`、布阵 UI（点选/拖拽/交换）、校验（25 子必须摆满 25 格）。
  - 双人同屏的遮罩/交接流程。
  - 可选的"己方半场明置"需要视图层（见 3.14 的信息模型说明），不建议在 MVP 做。
- 布阵模板本身可以做成数据（`[{name, cells:[...]}]`），方便以后加阵型包。

**风险**

- 完整版 UI 工作量大，且移动端拖拽体验需要专门打磨。
- "所有子背朝下 + 玩家记得自己的阵"对记忆力有要求；如果玩家反馈太累，再考虑"己方半场明置"的视图层。

**MVP 切法**：三套模板 + 布阵图按钮，先验证"布阵有没有人玩"，再投入拖拽。

### 3.8 每日挑战 / 残局　推荐 A　难度 ⭐⭐（MVP）/ ⭐⭐⭐

**核心规则**

- **每日挑战**：每天一个固定种子生成同一副牌局，所有人打同一局；记录本地最佳步数/用时/是否获胜，可分享战绩。
- **残局模式**：人工或半自动生成若干"少子残局"，给出目标（如"3 步内夺旗"/"红方必胜"），玩家挑战。
- 与经典规则一致，只是发牌与目标可复现。

**为什么好玩**

- 每日一局是低成本留存钩子；"同一局面，谁解得快"天然适合分享。
- 残局是高质量内容：短、难、可讨论，适合做成关卡包。

**实现要点**

- 引入 **种子化 RNG**：把 `js/state.js` 里 `shuffle`/`fillMirrorBoard`/随机分边用的 `Math.random`（`:25/:40/:67`）替换为可注入的 `rng`；`createInitialState({ seed })`。
- 每日种子 = 日期字符串哈希，保证跨设备一致。
- 残局需要"局面定义 + 目标 + 判定"：可以直接构造 `state.board` 的 JSON，配一个目标检查函数（现有 `checkWinner` 可复用一部分）。
- UI：首页/模式弹窗增加"每日挑战"入口、连续天数、最佳记录；本地存储即可，不需要后端。
- AI 的随机抖动（`ai.js:98/122/164`）如果要完全可复现，也要接受注入的 RNG；MVP 可只保证牌局一致，AI 允许随机。

**风险**

- 低。种子化是通用基础设施，做完后对测试、回放、每日挑战都有好处。
- 残局内容生产需要人工筛选，建议先做 10~20 关试水。

**MVP 切法**：每日固定种子 + 经典规则 + 本地最佳记录；残局放第二期。

### 3.9 逆战（以小博大）　推荐 B+　难度 ⭐⭐⭐

**核心规则**

- 普通棋子交战时**军衔低者胜**、同值同归；炸弹、地雷、军旗规则不变。
- 工兵仍然可以挖雷、铁路上仍可转弯。
- 需要平衡：逆战下工兵（rank 1）既是最强子又能挖雷，过强。可选方案：
  - 工兵在逆战模式视为 rank 4（中等），失去"最强"地位；
  - 或工兵失去挖雷能力，由其他子承担排雷；
  - 或炸弹数量 +1 作为工兵的克制手段。
  建议先用"工兵视为 rank 4"做 A/B。

**为什么好玩**

- 完全反直觉：司令变成最弱的累赘，工兵/排长变成宝贝；老玩家会被迫重新学习。
- 适合作为"整活"模式，直播/短视频效果好。

**实现要点**

- `resolveBattle` 增加可选参数 `cfg`（或第三参 `variant`）：比较时用 `effectiveRank(piece, variant)`。默认经典行为不变。
- 6 处调用点（`state.js:112`、`ai.js:132/185/222/610/653`）都要传入 `state.variant` 或 cfg；这是本玩法的主要成本。
- AI 估值：`valueOfPiece` 需要按玩法反转（司令便宜、工兵贵），`RANK_VALUE` 也要换表；否则 AI 会疯狂送司令。
- 走法排序的 MVV-LVA（`ai.js:610` 附近）依赖 `resolveBattle`，会自动跟随新规则。
- UI：规则说明需要明确"小官吃大官"和工兵的平衡设定。

**风险**

- 中高。规则函数签名扩散到 AI 多处，容易漏改；需要新增"逆战下 AI 不篡改状态/快照一致"的测试。
- 平衡难度高，工兵过强是结构性问题。

**MVP 切法**：先只反转普通子比较，工兵视为 rank 4；不做"工兵失去挖雷"。

### 3.10 战场事件　推荐 B+　难度 ⭐⭐⭐⭐

**核心规则**

- 每 8 个 ply（双方各 4 步）触发一次随机事件，事件对双方公平（随机选边/随机位置）：
  - **空投补给**：随机一颗普通子落在随机空格（非行营），明置或暗置二选一。
  - **地毯轰炸**：随机一条 3 格直线，炸掉其中所有棋子（军旗免疫；地雷被炸算已拔除）。
  - **紧急换防**：随机交换两颗**非军旗**棋子的位置（可限定为己方半场）。
  - **增援**：从阵亡名册里随机复活一颗子，放到己方后两排空格。
- 事件有 toast + 动画 + 音效，形成"战场突发"的节目效果。

**为什么好玩**

- 高随机、高戏剧性，适合派对/娱乐局；每一局都有意外。
- 可以做成"事件频率"可调（关 / 低 / 高），让玩家自己选择混沌程度。

**实现要点**

- 新增 `js/events.js`（纯函数 + 事件表），在 `applyMove` 换手后按 ply 计数触发；事件本身也走 `applyBattle` 或直接改 cell，必须保证可撤销/可序列化。
- 事件需要种子化，否则 AI Worker 与主线程可能算出不同事件；建议事件由主线程在动作落盘后生成，并把结果写进 `lastMove`，AI 只读快照。
- AI 无法预测随机事件：搜索里可以把事件当作"不发生"（AI 短视），或作为 chance 节点（成本高）。建议接受"AI 在事件局偏弱"的设定，并在玩法说明里注明"娱乐向，AI 强度下降"。
- 事件可能影响胜负/军旗/地雷计数，必须逐条定义边界（军旗免疫轰炸、换防不碰军旗、增援不复活军旗等）。

**风险**

- 高。事件是新的系统层，测试面大；AI 质量会下降；玩家可能觉得"输给随机"。
- 建议只在"娱乐/派对"分类里提供，不作为默认玩法。

**MVP 切法**：只做"空投补给"和"地毯轰炸"两个事件，频率固定每 8 ply。

### 3.11 炮火支援　推荐 B　难度 ⭐⭐⭐

**核心规则**

- 每方每局一次「炮击」：选择一个 3 格直线区域（同一行或同一列的连续 3 格），摧毁其中所有棋子。
- 军旗免疫（避免一炮终局）；地雷被炸算已拔除；炸弹被炸不额外爆炸。
- 炮击消耗整个回合，不能与走子同时进行。

**为什么好玩**

- 一次"大招"能清掉行营外的关键子，打破僵局；用得好是翻盘点，用不好是空炮。
- 与"拔雷"机制天然联动：一炮清掉两颗雷，打开吃旗通道。

**实现要点**

- 新增动作类型 `{kind:'strike', cells:[...]}`：`rules.enumerateActions` 在炮击可用时加入候选；`state.applyMove` 处理移除、`minesLost`、胜负判定。
- `ai.applyAction`/`applyOnClone` 需要支持新动作类型与 undo；AI 估值要能评估"炮击收益"（可用一次 1-ply 枚举）。
- UI 需要"炮击瞄准"模式（选中 3 格），以及剩余次数显示。
- 规则边界：不能炸行营？建议可以炸，但行营内棋子免疫（沿用行营免疫语义），或干脆禁选含行营的 3 格。

**风险**

- 中。新动作类型会波及 AI 枚举、搜索、悔棋、UI 选中；但边界清晰。
- 炮击强度需要 A/B；建议先设为"每局一次、军旗免疫、行营禁选"。

**MVP 切法**：只允许横向 3 格，禁含行营，军旗免疫。

### 3.12 王牌英雄　推荐 B　难度 ⭐⭐⭐

**核心规则**

- 每方随机一颗普通子成为「英雄」，拥有 **2 条命**。
- 英雄第一次被吃/同归时不死：原地保留（或撤退到己方后两排随机空格），军衔 -1（最低工兵），并标记"已负伤"。
- 第二次死亡按普通规则移除。
- 炸弹对英雄仍然是同归（英雄消耗一条命，炸弹消失）。

**为什么好玩**

- 一颗"打不死"的子会改变局部攻防，玩家会围绕英雄做保护和围杀。
- 与军衔升级有相似的成长感，但更集中、更有角色感。

**实现要点**

- `piece.lives` 字段；`applyBattle` 在判定死亡时检查 `lives > 1`，改为"存活 + 减命 + 降级"。
- AI：`valueOfPiece` 给英雄溢价；搜索里 `lives` 会随 make/unmake 变化，必须确保 undo 恢复（`applyBattle` 克隆替换 + `undoAction` 回填 cell 对象，天然兼容）。
- UI：英雄金冠/红心角标、负伤状态、播报。
- 复活落点要确定性（避免随机导致 AI 快照不一致）：优先原地保留，简单可靠。

**风险**

- 中。主要风险是"英雄 + 军衔升级"如果以后想组合会叠加过强；当前变体互斥，暂时不用担心。
- 平衡：英雄如果随机到工兵，双命意义不大；可以限定"英雄从团长及以上随机"。

**MVP 切法**：只给"司令/军长/师长"随机一颗英雄，双命、原地复活、不降级。

---

### 3.13 军饷系统　推荐 B-　难度 ⭐⭐⭐⭐

**核心规则**

- 吃子获得军饷（按被吃子价值折算）；军饷可购买：
  - 额外行动一次（2 军饷）
  - 侦察：随机揭示一颗敌方暗子（3）
  - 复活：从阵亡名册复活一颗子（5）
  - 炮击（6，可复用 3.11）
- 每回合最多购买一次，购买也消耗回合或作为附加动作（需定义）。

**为什么好玩**

- 给"吃子"增加第二层收益，形成经济滚雪球；玩家要在"买行动/买情报/买复活"之间做取舍。
- 适合作为长期 meta 系统，与每日挑战/闯关结合。

**实现要点**

- 新增 `state.coins = {red, blue}`、购买动作类型、UI 军饷条与商店弹层。
- AI 需要一套"经济估值"：军饷的边际价值、购买时机；这是主要成本。
- 与现有"一步一换手"模型冲突：购买是否占回合、能否在对手回合买，都要定义。
- 信息类购买（侦察）会触碰 `revealed` 的公开性，等于给一方额外信息，需要确保 AI 不偷看。

**风险**

- 高。经济系统 + 新动作 + AI 估值 + UI，接近一个小型资料片；不建议在玩法数量还没铺开时做。
- 如果未来要做组合式 modifier，军饷更适合作为"修饰器"而不是独立 variant。

---

### 3.14 迷雾行军　推荐 B-　难度 ⭐⭐⭐⭐

**核心规则**

- 棋子移动后**重新盖回**（位置已知、身份未知）；停在原地不动的子保持明置。
- 再次翻开需要消耗一步；交战前自动揭示。
- 双方都只能看到"公开信息 + 自己的记忆"。

**为什么好玩**

- 记忆与欺骗：你可以把司令藏成工兵，也可以让对手误判你的强子位置。
- 中后期棋盘会变成"半明半暗"的信息战，和经典翻翻棋有本质区别。

**实现要点（也是本玩法最大的坑）**

- 当前 `cell.revealed` 是**双方共享的公开信息**：一旦设为 `false`，连棋子主人自己也无法在 UI 上选中它，`legalMoves` 会拒绝，`enumerateActions` 会把它当成可翻的暗子。
- 要做到"己方可见、敌方不可见"，必须新增视图层（例如 `state.knowledge = { red: {...}, blue: {...} }` 或 `viewFor(state, side)`），把"规则状态"和"玩家视图"分开。这是一次 C3 级改造，会影响 UI、AI、Worker 快照。
- 双人同屏天然无法隐藏（两人看同一块屏幕），只能靠"按住查看/交接遮罩"，体验会打折。
- AI 目前把未翻子当"未知分布"处理，这恰好符合"AI 也忘了"的设定；但玩家有记忆、AI 没有，会形成不对称。可以接受（AI 不放水），也可以给 AI 加一个"记忆表"。

**风险**

- 信息模型改造是当前架构最大的空白；做完后对"迷雾/布阵明置/侦察"等一批玩法都有复用价值，但单为这一个玩法做不划算。
- 建议：**先不做**，等 3.7 完整版或 3.13 侦察需求出现时，再统一做视图层。

---

### 3.15 Roguelike 闯关　推荐 C（远期）　难度 ⭐⭐⭐⭐⭐

**核心规则**

- 连续挑战 5~10 个残局/小局，棋子、军衔、军饷、遗物在关卡间继承；失败即结束一轮。
- 每关后三选一增益（如"工兵战力 +1"/"开局多一颗炸弹"/"每局一次悔棋"）。
- 需要存档、元进度、内容生成与平衡。

**为什么好玩**

- 长期留存最强：每轮不同、有成长、有 Build 组合。
- 与每日挑战、军饷系统天然契合。

**实现要点**

- 需要：种子化、残局定义、跨局状态、存档、增益系统、UI 流程、AI 难度曲线。
- 基本是一个独立资料片的体量，不建议在当前阶段启动。

## 4. 推荐路线图

### v1.5：一个爽点 + 一个体验点（约 1 周）

- **招降纳叛**（S，⭐⭐）：规则爽点，改动集中在 `applyBattle`。
- **闪电战**（A，⭐）：移动端体验点，纯 UI/调度。
- 理由：一个改玩法、一个改节奏，风险低，能快速验证"新娱乐模式"的接受度。

### v1.6：连击 + 每日挑战（约 1~2 周）

- **乘胜追击**（S，⭐⭐⭐）：高光玩法，但需要认真做 AI 与悔棋。
- **每日挑战 MVP**（A，⭐⭐）：种子化 + 本地最佳记录，补留存。
- 理由：连击是"传播型"玩法；每日挑战是"回访型"内容，二者互补。

### v1.7：快棋包（约 1 周）

- **火药桶** + **无雷速攻** + **夺旗行军**（均 ⭐~⭐⭐）。
- 三个都依赖"变体棋子数量/走法"的小改造，可以共用一套 `variantConfig`。
- 在模式弹窗里新增「快棋」分类，避免玩法按钮无限膨胀。

### v2.0：旗舰内容（约 2~4 周）

## 5. 架构前置改造建议

如果只做 1~2 个玩法，可以继续用现有 `if (variant === …)` 分支；但如果按上面的路线铺到 6~8 个玩法，建议先做三件小事：

### 5.1 变体配置表（优先）

新增 `constants.variantConfig(variant)`，返回一个纯数据对象：

```js
{
  pieceCounts: { bomb: 4, company: 2, ... },
  minesRequired: 3,
  immobile: ['mine'],          // 军旗是否可动
  battleMode: 'classic' | 'invert' | 'convert',
  turnMode: 'classic' | 'chain',
  staleLimit: 80,
  infoMode: 'public' | 'perSide',
}
```

让 `buildPieces`、`remainingDistribution`、`trackerData`、`legalMoves`、`resolveBattle` 都从 cfg 取值，而不是各写各的 `if`。这是以后加玩法不失控的关键。

### 5.2 规则函数显式收 cfg

`resolveBattle(attacker, defender, cfg)`、`legalMoves(state, index, cfg?)`。默认参数保持经典行为，现有测试不用改。AI 的所有调用点统一传 `state.variant` 对应的 cfg。

### 5.3 种子化 RNG

把 `js/state.js` 的 `Math.random` 换成可注入的 `rng`（mulberry32 之类），`createInitialState({ seed })`。收益：每日挑战、残局、回放、可复现测试。音频/粒子/UI 的随机不必种子化。

### 5.4 信息可见性（远期）

如果确定要做迷雾/明置半场，新增 `viewFor(state, side)`，不要复用 `cell.revealed` 表达"某方可见"。当前 AI 的"不作弊"契约依赖 `revealed` 只表示公开信息；一旦混用，AI 会读到不该读的东西。

### 5.5 玩法选择 UI

现有模式弹窗是一个 3 按钮 seg（`index.html:96`），再加 5 个玩法会挤爆移动端。建议：

- 分两行/分组：「经典」+「娱乐」+「快棋」+「挑战」；
- 或改成可横向滚动的卡片列表，每张卡带一句玩法说明与难度标签；
- 金标 `#variant-badge` 文案从 `if (isMirror) … else …` 改为查表。

### 5.6 测试矩阵

每个新玩法至少覆盖：

- `applyBattle` 新分支的所有结果（胜/负/同归/特殊子/边界）；
- AI make/unmake 后 `boardSig` 逐位一致（现有快照一致性测试扩展 variant）；
- 悔棋后状态与走子前逐位一致；
- 终局/和棋/无路可走优先级不被破坏；
- 记牌器在变体数量/策反下的计数不出现负数（或明确隐藏）。

## 6. 风险清单

| 风险 | 涉及玩法 | 缓解 |
|---|---|---|
| 雪球过强 | 招降纳叛、乘胜追击、王牌英雄 | 上限/降级开关 + A/B |
| AI 质量下降 | 战场事件、连击、炮击 | 注明"娱乐向"；AI 只做 1~2 层适配 |
| 信息泄露（双人同屏） | 自选布阵、迷雾 | 遮罩/按住查看；或双人模式禁用 |
| 记牌器口径 | 火药桶、无雷、招降 | `variantConfig` + 负数夹紧/隐藏透视 |
| 规则函数签名扩散 | 逆战 | 先做 cfg 配置表，再改 5 处调用点 |
| 玩法按钮膨胀 | 全部 | 模式弹窗分组/卡片化 |
| 测试成本 | 全部 | 复用现有 boardSig/快照一致性测试 |

## 7. 附：按成本排序的速查

| 成本 | 玩法 | 推荐 |
|---|---|---|
| ⭐ | 闪电战、无雷速攻 | A / B+ |
| ⭐⭐ | 招降纳叛、火药桶、夺旗行军、自选布阵 MVP、每日挑战 MVP | S / A / A- / S / A |
| ⭐⭐⭐ | 乘胜追击、逆战、炮火支援、王牌英雄 | S / B+ / B / B |
| ⭐⭐⭐⭐ | 自选布阵完整版、战场事件、军饷、迷雾 | S / B+ / B- / B- |
| ⭐⭐⭐⭐⭐ | Roguelike 闯关 | C |

**如果只能选一个先做**：**招降纳叛**。它只碰 `applyBattle`，却能把整个游戏的交换逻辑翻新一遍，是当前性价比最高的娱乐玩法。

**如果只能选一个做旗舰**：**自选布阵**。它最像"真正的军棋"，也最能撑起一个版本，但请从模板 MVP 开始。
